# Перенос на сервер — инструкция

## Что нужно знать про игру

| Параметр | Значение |
|---|---|
| Тип приложения | Node.js + Express + Socket.IO (WebSocket) |
| Фронтенд | Phaser 3, собирается Vite в `dist/` |
| Порт | `PORT` (по умолчанию 3002) — платформа задаёт сама |
| Health-check | `GET /health` → `{"ok":true,...}` |
| WebSocket | Тот же домен, путь `/socket.io` |
| Сохранения | `data/rooms.json`, `data/player-profiles.json` — **нужен постоянный диск** |
| Node.js | >= 22.13 |

Главное: клиент и сервер живут на **одном домене**. Клиент подключается к
`window.location.origin`, поэтому ничего прописывать не нужно. Домен
получится вида `https://quiet-garden.onrender.com` — он и будет адресом игры.

---

## Вариант 1. Render.com (проще всего, но сохранения не переживают рестарт)

1. Залейте проект в GitHub (нужен git-репозиторий).
2. На [render.com](https://render.com) → **New → Web Service** → подключите репозиторий.
3. Настройки:
   - Runtime: **Docker**
   - Dockerfile path: `./Dockerfile`
   - Health Check Path: `/health`
   - Plan: **Free**
4. Нажмите **Apply** — Render сам соберёт образ и запустит.

Через ~2 минуты игра будет доступна на `https://<имя-сервиса>.onrender.com`.

**Минусы free-плана:**
- Засыпает через 15 минут без трафика, просыпается ~1 минуту.
  Для игры это значит: первый игрок после паузы ждёт подключения.
- Диск эфемерный → `data/` очищается при каждом рестарте и деплое.
  Комнаты и профили игроков будут теряться.
- Render может перезапустить сервис в любой момент.

**Кому подойдёт:** если важно «просто запустить и показать друзьям», а прогресс
не жалко терять. Единственный вариант, где вообще не нужна карта.

## Вариант 2. Northflank (рекомендую — не засыпает + есть диск)

Free-план (Developer Sandbox): 2 сервиса, 1 база, до $20/мес ресурсов,
**всегда включён** — не засыпает.

1. Залейте проект в GitHub.
2. На [northflank.com](https://northflank.com) → **Create → Service → Add from Dockerfile**.
3. Укажите репозиторий и `Dockerfile` из корня.
4. В разделе **Volumes** создайте volume и примонтируйте в `/app/data` —
   это сохранит комнаты и профили при рестартах.
5. Health check: `/health`, порт `3002`.
6. Переменные: `NODE_ENV=production`, `PORT=3002`.

Готовый конфиг лежит в `northflank.yml`.

**Минусы:** нужна карта для регистрации; free-период ограничен по ресурсам.

---

## Вариант 3. Koyeb (бесплатно, но засыпает через час)

1. GitHub → [koyeb.com](https://www.koyeb.com) → **Create Service → Dockerfile**.
2. Instance: **free**, регион **fra** (Франкфурт — ближе всего к РФ).
3. Health check: `/health`.
4. Volume на free-инстансе недоступен → сохранения не переживают рестарт.

Готовый конфиг — `koyeb.yaml`.

---

## Вариант 4. VPS (если нужна полная надёжность и бесплатно навсегда)

**Oracle Cloud Always Free** — до 4 ядра ARM / 24 ГБ RAM бесплатно навсегда:
- Регистрация: [oracle.com/cloud/free](https://www.oracle.com/cloud/free/)
- Создать VM.Standard.A1.Flex (2 OCPU, 12 GB RAM) в home-регионе
- Если «out of host capacity» — поменять регион или подождать несколько дней
- Ставим Docker, копируем проект, `docker run` с volume на `/app/data`
- Открываем порт 3002, привязываем свой домен

**Google Cloud Free Tier** — 1 × e2-micro (1 GB RAM) бесплатно:
- [cloud.google.com/free](https://cloud.google.com/free)
- Регионы: `us-west1`, `us-central1`, `us-east1`
- 1 GB исходящего трафика в месяц — для игры хватит

**Важно про карты:** Oracle и Google при регистрации просят карту для проверки
и **списывают небольшую сумму** (~$1, которую возвращают). Российские карты
могут не пройти — тогда нужна иностранная.

## Как проверить, что всё задеплоилось

```bash
curl https://<ваш-домен>/health
# {"ok":true,"uptime":42,"rooms":0}
```

Дальше откройте домен в браузере, введите ник, нажмите **«Войти»** —
появится код комнаты из 6 символов. Откройте этот домен на втором
устройстве (или в другой вкладке), введите тот же код — игроки должны
увидеть друг друга.

## Если хочется «просто один раз поиграть с друзьями»

Можно вообще без хостинга: раздать локальную сеть. Но чтобы друзья из
другого города зашли к вам, нужен внешний адрес — это уже как раз требует
хостинг или туннель (ngrok/Cloudflare Tunnel).

---

## Итоговая рекомендация

1. **Хочется прямо сейчас, без карты** → Render.com (но прогресс сбрасывается).
2. **Хочется нормально и надолго** → Northflank + volume, или Oracle Cloud Always Free.
3. **Хочется бесплатно навсегда и без ограничений** → Oracle Cloud Always Free (VPS).
