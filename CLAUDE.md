## Build / Test / Lint

| Command | What it does |
|---|---|
| `pnpm install` | Install dependencies |
| `pnpm run dev` | Start Vite dev server (client) at http://localhost:5174 |
| `pnpm run server` | Start Node.js + Socket.IO server at http://localhost:3002 |
| `pnpm start` | Start both server and client simultaneously |
| `pnpm run build` | Production build (client → dist/) |
| `pnpm run preview` | Preview built version locally |
| `pnpm run check` | Syntax-check server/*.js + run vite build |
| `pnpm test` | Run tests: `node --test 'tests/*.test.js'` |

## Environment

| Variable | Default | Description |
|---|---|---|
| `PORT` | `3002` | Server HTTP/WebSocket port |
| `VITE_SERVER_URL` | same-origin | Set only if server on separate domain |
| `KEEP_ALIVE_INTERVAL_MS` | `600000` (10 min) | Self-ping interval; auto Resolves via `RENDER_EXTERNAL_URL` on Render |
| `.env` | — | Copy `.env.example` to `.env` as needed; `.env` is gitignored |

**Important**: `.env` is gitignored. If you need environment variables, copy `.env.example` to `.env`.

## Server

- Server serves `dist/` as static root in production; `index.html` in dev.
- Health check: `GET /health` → `{ok, uptime, rooms}`
- Rooms live 7 days; data (`rooms.json`, `player-profiles.json`) resets on restart/deploy for free platforms (Render/Koyeb free).
- Max 4 players per room.
- Keep-alive only works with public URLs — does NOT ping localhost.

## Project structure (high-level)

```
server/         # Node + Socket.IO handlers
shared/         # Client+server shared code
src/            # Client (Phaser 3)
data/           # Auto-created saves (gitignored)
dist/           # Production build (generated by `pnpm run build`)
```

## Testing

- Run all tests: `pnpm test`
- To run a single test: `node --test 'tests/<name>.test.js'`
- Tests use `node --test` (built-in test runner)

## Gitignored / Runtime data

- `data/` contains `rooms.json` and `player-profiles.json` — auto-created at runtime, gitignored
- On free platforms (Render, Koyeb), these files **reset on every restart/deploy**
- For persistent savings, use a VPS with permanent disk or a platform with attachable volume

## Health check

`GET /health` always returns `{ok: true, uptime: N, rooms: M}` — use this to verify the server is running.
